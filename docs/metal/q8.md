# Metal Q8 weights

`--metal-weight-format q8` reduces the resident storage of the four repeated
DiT matrices in each of the 50 blocks. It is independent of dense/SOL attention
and attention precision. The default weight format remains `bf16`.

For a short Q8 + conservative SOL render:

```sh
./bin/h3cli -d models/MiniMax-H3 -p "A person walks through a sunny park. Birds sing softly." \
  --width 640 --height 480 --frames 243 --steps 6 \
  --backend metal \
  --metal-weight-format q8 --metal-q8-kernel mpsgraph \
  --metal-attention sol --metal-attention-kernel steel-routed \
  --metal-attention-dtype fp16 --metal-attention-layout adapter \
  --sol-min-exact .75 --sol-dense-steps 1 --sol-dense-sigma .99 \
  --preview-vae -o outputs/q8-sol.mp4
```

Use `--metal-attention dense` to remove SOL routing from that comparison. Use
`--metal-weight-format bf16` for the otherwise identical BF16-weight baseline.
The original dense BF16 oracle remains `--backend mpsgraph --metal-attention dense`.

Q8 is opt-in. [M6 measurements](m6-q8-results.md) show about 40% less
observed memory with approximately unchanged denoising time, but the final
clips fail frozen visual screens; SOL also fails audio-envelope screens.
The six-step measurements do not qualify a 50-step
trajectory or the held-out conditioning/continuation corpus. The example uses
the preview VAE; M6's B6 quality comparisons use the production VAE.

## Storage and execution

Recipe 1 packs each output row into symmetric signed int8 groups of 64 along
the input dimension, with FP32 scales and round-to-even conversion. The 200
core matrices occupy 20.472 GB instead of 38.535 GB, a 46.875% reduction for
those weights. Other weights and runtime allocations retain their normal
formats, so total process memory does not fall by that same percentage.

Packing reads the original BF16 checkpoint at startup using at most 8 MiB of
temporary CPU staging. Original model files and resolved runtime LoRA folds
are unchanged. There is no persistent Q8 cache; each new model context packs
its own resident weights. Warm reuse of a prepared context retains them.

Two explicit policies are available:

| `--metal-q8-kernel` | Computation | Intended use |
| --- | --- | --- |
| `mpsgraph` (default) | Metal dequantization into bounded BF16 scratch, then MPSGraph GEMM | Memory-saving M4 path |
| `simdgroup` | Native tiled Q8/BF16 linear, FP32 operands and accumulation, BF16 output | Portable native kernel; slower in measured M4 projections |

The default policy reuses one expanded matrix buffer per projection shape
across all blocks: approximately 0.771 GB in total. It does not retain an
expanded copy of every weight. Both policies preserve BF16 activations,
explicit BF16 SwiGLU and the existing BF16/FP32 residual path. This is
weight-only quantization; it does not introduce INT8 activation arithmetic.

Q8 currently requires resident Metal execution, 50 layers,
reuse 1, and ANE off. SSD streaming and CUDA Q8 are unsupported. Native M5
INT8 arithmetic requires separate implementation and qualification.

Sampler checkpoints record Q8 recipe, group size and kernel policy in a
required section. Readers without Q8 support reject that section. Prepared
DiT keys distinguish BF16/Q8 and the two Q8 policies; conditioning caches can
be reused because their tensors are independent of core weight storage.

## Reproducing validation

```sh
make -j4 bin/h3cli bin/metal_q8
./bin/metal_q8
./bin/metal_q8 --bench models/MiniMax-H3/FL2VA/transformer 22426 0 mpsgraph
python3 scripts/metal_native_freeze.py --output outputs/q8-frozen
python3 scripts/metal_q8_validate.py --frozen outputs/q8-frozen --output outputs/q8-runs
python3 scripts/metal_q8_report.py --runs outputs/q8-runs --output outputs/q8-review --quality
```

The operator harness accepts projection indices 0–3 for QKV, attention
output, FC1 and FC2, and either kernel policy. The render harness runs serial
B1/B5/B6 ablations at 640×480/243 frames with a hard six-evaluation ceiling.
It retains a frozen executable/source snapshot, conditioning, logs, tensor
checksums, videos and AV states. Resume rejects changed retained artifacts.
The quality report uses the pinned environment in
[`requirements-metal-quality.txt`](../../tests/requirements-metal-quality.txt).

Report Q8 dense against BF16 dense, and Q8 SOL against BF16 SOL. Attention
and SOL gains are separate comparisons against Reference+. B5 excludes
diagnostic tensor capture; B6 uses six independent evaluations and the
production VAE. Final HTML pages provide paired playback without requiring
a human-review gate. Failed screens remain failed, and Q8 remains opt-in.
